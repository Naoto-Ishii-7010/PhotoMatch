# Create PR

## ワークフロー

### Step 1: コード差分を取得する

```bash
git diff develop...HEAD
```

を実行し、差分を PR 説明文生成のコンテキストとして使用する。
マージ先ブランチが指定された場合はそのブランチとの差分を使用する（例: `git diff main...HEAD`）。

### Step 2: テンプレートを読み込む

`.github/PULL_REQUEST_TEMPLATE.md` を読み込み、構造を確認する。

### Step 3: PR説明文を生成する

読み込んだテンプレートの構造に厳密に従ってPR説明文を生成する。

**ガイドライン:**

- 必ず日本語で記述する
- PRタイトルも生成する
- 変更の「内容（What）」だけでなく「目的（Why）」に焦点を当てる
- レビュアーが迅速に意図と内容を把握できるよう、重要な情報は冒頭に配置する
- 必ずMarkdown形式のコードブロックで出力する

**各セクションの方針:**

- 「概要」: 変更の「目的」と「背景」を最優先で記述する
- 「関連するURL」: 関連するGitHub Issueを自動検出し、なければ「なし」と提案する
- 「原因」「対応」: バグ修正や問題対応の場合のみ記述し、それ以外は省略する
- 「TODO」: コードの複雑さや未完了タスクが推測される場合のみ生成し、それ以外は省略する
- 「スクリーンショット」: UIに関連するファイル変更（`.tsx`, `.css`, `.scss` 等）がある場合のみ `| Before | After |` 形式で提案し、それ以外は「UI変更なし」と記述する
