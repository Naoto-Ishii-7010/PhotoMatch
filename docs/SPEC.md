## 1. サービス概要

### サービス名

**PhotoMatch**

### 一言説明

写真撮影を依頼したいユーザーと、趣味または副業として撮影を行うフォトグラファーをつなぐ、C2C 写真撮影マッチングサービス。

### 背景

- プロスタジオへの依頼は高額になりやすく、日常的な撮影需要に対してハードルが高い
- スマートフォン写真では満足できないが、プロへ依頼するほどではない用途が多い
- 趣味で撮影スキルを持つフォトグラファーが、無理のない範囲で依頼を受ける場が少ない

### 解決したい課題

- 気軽に撮影を依頼できる価格帯の選択肢を増やす
- フォトグラファーが自分の作品を公開し、受注機会を得られるようにする
- 知らない相手とのやり取りでも、最低限の安全性と透明性を担保する

---

## 2. 対象ユーザーと役割

**対象国**: 日本のみ

**提供言語**: 日本語のみ

### 主なユーザー

- **依頼者**: 家族写真、プロフィール写真、記念日、ペット、イベントなどを撮影してほしいユーザー
- **フォトグラファー**: 趣味または副業として撮影を行い、依頼を受けたいユーザー
- **運営管理者**: 通報対応、アカウント停止、トラブル一次対応を行う管理ユーザー

### 役割に関する前提

- 1つのアカウントで依頼者・フォトグラファーの両方を兼ねられる
- 閲覧中心の機能は未ログインでも利用できる
- 依頼、提案、フォロー、チャットはログイン必須

## 3. MVP スコープ

### 今回作るもの

- Google 認証による登録・ログイン
- プロフィール管理
- ポートフォリオ管理
- 依頼者向け検索（フォトグラファー検索・作品検索）
- フォトグラファー向け案件検索
- 指名型依頼
- 公募型依頼、提案比較、提案選択
- マッチ成立後の1対1チャット
- プッシュ通知、アプリ内通知
- 運営管理画面

### 今回作らないもの

- アプリ内決済、請求、返金
- レビュー、星評価
- 画像添付付きチャット
- メール通知、SMS 通知
- 自動本人確認、自動モデレーション

## 4. 主要ユーザーフロー

### 依頼者がフォトグラファーを探して直接依頼する流れ

1. Google アカウントで登録する
2. プロフィールを設定する
3. 検索または作品閲覧からフォトグラファー詳細ページへ進む
4. 指名型依頼を送る
5. フォトグラファーが承認するとマッチ成立
6. チャットで日時、場所、料金、支払い方法を調整する
7. 撮影実施後、双方が完了操作を行う

### 依頼者が公募して提案を比較する流れ

1. 依頼内容を公募として投稿する
2. 複数のフォトグラファーから提案を受け取る
3. 提案内容、プロフィール、作品を比較する
4. 1名を選択してマッチ成立させる
5. 以降はチャットで調整し、撮影完了後に完了操作を行う

### フォトグラファーが案件を探して提案する流れ

1. プロフィールとポートフォリオを公開状態にする
2. 案件検索で公募を探す
3. 条件に合う案件へ提案を送る
4. 依頼者に選ばれるとマッチ成立
5. チャットで詳細を調整し、撮影完了後に完了操作を行う

## 6. 共通ビジネスルール

### アカウント・プロフィール

- Google アカウントの `sub` をユーザーの一意識別子として扱う
- サービス内に公開するプロフィールと、運営管理用の連絡先メールアドレスは分離する
- 依頼者として依頼や公募を行うには、少なくとも `表示名` の設定が必要
- フォトグラファーとして検索掲載や提案を行うには、`表示名`、`活動エリア`、`対応ジャンル`、`自己紹介` の設定と、公開ポートフォリオ1件以上を必須とする

### 公開情報と非公開情報

- 未ログインユーザーに公開されるのは、プロフィール公開情報、公開ポートフォリオ、公開中のフォトグラファー検索結果のみ
- 依頼前の段階では、依頼者の正確な住所、電話番号、支払い手段などの個人情報は公開しない
- 依頼・公募では `都道府県` と `市区町村` までを必須入力とし、待ち合わせ場所や詳細住所はマッチ成立後にチャットで共有する

### 料金・支払い

- サービス上の予算や提案金額は、撮影料の目安として扱う税込み総額の金額（円）とする
- 交通費、入園料、施設使用料などの実費を含むかどうかは補足事項またはチャットで明示する
- 決済は当事者間で直接行い、サービスは請求、支払い確認、返金を管理しない

### キャンセル

- マッチ成立前の依頼キャンセル、公募キャンセル、提案取り下げは理由入力なしで実行できる
- マッチ成立後のキャンセルは、当事者のいずれからでも実行できるが、理由入力を必須とする
- キャンセル料の計算、徴収、返金はアプリでは扱わない
- キャンセルが発生した場合、対象案件は `キャンセル` となり、理由を監査ログに残す

### 完了

- 撮影と支払いが終わったら、当事者が案件を `完了待ち` に進められる
- 双方が完了操作を行った時点で `完了` とする
- 片側のみが完了操作を行った場合は `完了待ち` を維持し、7日以内に相手の操作がなければ自動で `完了` にする

### 禁止事項

- 連絡先、詳細住所、外部 SNS への誘導を公開プロフィールや公開ポートフォリオに掲載すること
- 権利侵害画像、第三者の個人情報が含まれる画像、わいせつまたは違法な内容の掲載
- 成約前にサービス外へ誘導することを主目的としたメッセージ送信

## 7. 案件の共通データ項目

指名型依頼、公募型依頼で扱う主要項目は以下で共通する。

| 項目         | 必須 | 内容                                   |
| ------------ | ---- | -------------------------------------- |
| 撮影ジャンル | 必須 | 検索仕様で定義するジャンルから選択する |
| 希望撮影日   | 必須 | 日付、または日付付きの日時候補         |
| 撮影エリア   | 必須 | 都道府県、市区町村                     |
| 予算         | 必須 | 円単位の整数                           |
| 補足事項     | 任意 | 要望、条件、交通費扱いなど             |

公募型依頼のみ、`募集締切日時` を追加で必須とする。

## 8. 案件の状態管理

| 状態       | 概要                                                         |
| ---------- | ------------------------------------------------------------ |
| 募集中     | 依頼作成後、承認または提案を待っている状態                   |
| 提案中     | 公募に1件以上の提案が届き、依頼者が比較検討している状態      |
| マッチ成立 | 指名依頼の承認、または公募での提案選択が完了した状態         |
| 進行中     | マッチ成立後、チャットで具体調整を開始した状態               |
| 完了待ち   | 撮影と支払いが完了し、双方の完了操作または自動完了待ちの状態 |
| 完了       | 案件がクローズした状態                                       |
| キャンセル | 当事者都合、期限切れ、停止対応などで終了した状態             |

### 状態遷移ルール

- 指名型依頼は `募集中` → `マッチ成立` → `進行中` → `完了待ち` → `完了`
- 公募型依頼は `募集中` → `提案中` → `マッチ成立` → `進行中` → `完了待ち` → `完了`
- 指名型依頼の承認待ちは72時間で失効し、`キャンセル` に遷移する
- 公募型依頼は募集締切後、新規提案を受け付けない
- `マッチ成立` 後に当事者のいずれかが最初のチャットメッセージを送信した時点で `進行中` に遷移する
- `完了` または `キャンセル` になった案件は再オープンしない

### キャンセル理由の管理

- キャンセルには `依頼者キャンセル`、`フォトグラファー辞退`、`募集期限切れ`、`承認期限切れ`、`運営停止` などの理由区分を保持する
- 画面上はまとめて `キャンセル` と表示し、詳細理由は当事者向け履歴と運営管理画面で確認できる

---

## 9. 安全性・運営対応

- 通報導線はチャット画面、案件詳細画面、プロフィール画面から提供する
- 停止されたユーザーはログイン不可とし、公開プロフィールや公開ポートフォリオを検索結果から除外する
- 停止されたユーザーが関与する募集中または進行中案件は、運営判断で `キャンセル` にできる
- 運営操作はすべて管理画面で監査ログを残す

---

## 10. 非機能要件

- 主要機能は PC とモバイルの双方で利用しやすいレスポンシブ UI として設計する
- 日本時間を基準に日時を扱う
- 金額表示はすべて日本円、3桁区切りで表示する
- 画像はアップロード後にサムネイル生成を行い、一覧表示での通信量を抑える
- 公開検索ページは SEO を考慮し、未ログインでも閲覧可能にする
